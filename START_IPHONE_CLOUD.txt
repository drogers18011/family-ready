WHAT IS INCLUDED
-----------------
codemagic.yaml supplies two workflows, both started manually:
- ios-compile-check: compile an unsigned iOS release; no Apple credentials.
- ios-testflight: build a signed internal-testing beta and upload it to App
  Store Connect. You then assign yourself to the build in TestFlight manually.

There are no push/scheduled triggers or tester invitations. The signed workflow
does not publish to the public App Store or submit an external beta review.

During a build, Flutter generates the native iOS host in a temporary
.cloud_build folder on the hosted Mac. Scripts copy this app's source into it.
The source folder and Windows browser launcher are preserved.

STEP 5 - APPLE SIGNING, AFTER THE COMPILE CHECK PASSES
-----------------------------------------------------
These are your own account, identity, agreement, and purchase actions. The
provided files do not perform them automatically.

A. Enroll and register the app
1. Review https://developer.apple.com/programs/enroll/ and enroll if needed.
   Choose individual or organization ownership to match how you intend to
   publish the app. Complete Apple's identity and payment steps yourself.
2. When membership is active, open Certificates, Identifiers & Profiles at
   https://developer.apple.com/account/.
3. Register an explicit App ID. The proposed bundle identifier is:
     com.dennisrogers.familyready
   It is not registered or reserved. If unavailable, choose another identifier
   and change all three identifier values in codemagic.yaml to match:
   FR_BUNDLE_ID in both workflows and the signed workflow's bundle_identifier.
4. At https://appstoreconnect.apple.com/, add a new iOS app record:
     Name: Black Box (subject to availability in App Store Connect)
     Primary language: English (U.S.)
     Bundle ID: the exact registered identifier
     SKU: family-ready-ios-001 (or another unique internal value)
   Creating the record does not release the app publicly.

B. Connect Apple's API key directly to Codemagic
1. In App Store Connect, open Users and Access > Integrations > App Store
   Connect API. Follow prompts if API access must first be requested.
2. Generate a dedicated key for Codemagic with App Manager access, following
   the current Codemagic signing guide in the references below.
3. Keep the Issuer ID, Key ID, and downloaded .p8 private key securely. Apple
   allows the private key to be downloaded only once.
4. In Codemagic account settings, open the Developer Portal integration
   (the UI may call this Integrations or Team integrations).
5. Add it with this exact integration name:
     family-ready-app-store
6. Enter the identifiers and upload the .p8 directly in Codemagic. Do not put
   your Apple password/private keys in chat, GitHub, or the project ZIP.

C. Add the matching signing certificate and profile
The API integration alone is not sufficient.
1. Open Codemagic settings > codemagic.yaml settings > Code signing identities.
2. In iOS certificates, choose Generate certificate, Apple Distribution, and
   the family-ready-app-store API integration.
3. Follow the download/upload prompts so the certificate and private signing
   key are available in Code signing identities. A suggested reference name
   is family-ready-distribution. Keep downloaded files/passwords securely.
4. In Apple's developer portal, create an App Store Connect distribution
   provisioning profile for the exact App ID and the new certificate.
   The TestFlight route does not require a device UDID list.
5. In Codemagic's iOS provisioning profiles tab, fetch or upload that profile.
   A suggested reference name is family-ready-appstore.
6. Confirm that Codemagic shows a matching certificate for the profile.

Keep the personal Codemagic account. Apple's use of the word "team" identifies
your Apple developer identity; it does not require a paid Codemagic Team plan.
